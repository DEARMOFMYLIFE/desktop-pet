## 1. 为什么选这两套

前两版角色分别使用程序化 PIL 绘制和像素画，观感不符合“可爱、现代、非像素”的要求。
Cute Girl 与 The Boy 都是扁平矢量、粉彩配色的 Q 版角色：

- 大头、大眼睛，现代扁平配色
- 原生 **Idle / Walk / Run / Jump / Dead** 五组高清逐帧动画
- 原生动画就是全身运动：头发、身体、双臂、双腿一起动
- CC0，可商用、可修改、无需署名

用户确认的预览：

- `docs/previews/cute-girl-preview.gif`
- `docs/previews/cute-girl-preview.png`
- `docs/previews/cute-girl-idle-large.png`

## 3. 11 个动作的来源

| 状态 | 来源 | 循环 | 帧数 / fps |
|---|---|---|---|
| `idle` | 原生 `Idle`（全帧 + 眨眼） | 是 | 16 / 10 |
| `walk` | 原生 `Walk`（全帧） | 是 | 20 / 14 |
| `sit` | 自定义：坐姿 + 软垫 + 呼吸浮动 | 是 | 6 / 4 |
| `sleep` | 原生 `Dead` 末段躺姿 + Zzz + 微动 | 是 | 8 / 4 |
| `focus` | 原生坐姿 + 膝上打开的书 + 呼吸 | 是 | 6 / 4 |
| `break` | 原生 `Jump` 慢速循环（伸懒腰/轻跳） | 是 | 16 / 8 |
| `celebrate` | 原生 `Jump` + 星星 | 否 | 16 / 12 |
| `drag` | 原生 `Jump` 空中段 + 左右摆动 | 是 | 10 / 10 |
| `react` | 原生 `Jump` 起跳段 + 感叹号 | 否 | 10 / 14 |
| `remind` | 原生 `Jump` 挥手段 + 动作弧线 | 是 | 10 / 8 |
| `droop` | 自定义：前倾、下沉、蓝色汗滴 | 是 | 6 / 4 |

- `sit` / `focus`：从 Idle 帧中移除白色腿部，整体下移，坐在软垫上；软垫颜色取裙子色相的 +0.25 类比色，避免与头发/裙子撞色。
- `focus` 只叠加膝上书与接触阴影，不覆盖角色手臂/手部；书本封面取当前服装主色，保持原生角色的平滑边缘。
- `sleep`：Dead 动画最后 8 帧是闭眼侧躺，直接在头顶绘制漂移的 Zzz。
- `break` / `celebrate` / `drag` / `react` / `remind`：复用原生 Jump 的不同段落，并叠加不同装饰，保证全身运动。
- `idle` / `sit` / `focus` / `droop` 各加入一帧眨眼，避免脸部长时间完全静止。
- 所有状态共用同一脚底锚点和缩放，切换状态不跳位。
- 男孩素材使用同一 11 状态契约，源动画为 15 帧；`idle` / `walk` 使用 15 帧，`sleep` 取躺姿末段 8 帧，其余动作复用 Jump 片段。

## 4. 资源规格

- 单帧：**200×200** 透明 WebP（`quality=90, method=6`）
- 每状态 6–20 帧横向排列
- `manifest.json`：`version: 4`、`frameSize: [200,200]`、`anchor: [0.5,1.0]`
- 每个风格/皮肤：11 个 `.webp` + `manifest.json` + `preview.png`（256×256）
- 资源路径：`frontend/public/assets/character/<style>/<skin>/`
- 无 PNG 回退：WebView 原生支持 WebP；Linux 原生渲染器使用 `image` crate 解码 WebP
- 8 种风格共 128 套皮肤（32 套经典配色 + 96 套主题角色配色），约 1664 个资源文件

裁剪/合成方式：

- 女孩：Idle / Walk / Jump：以源画布底部为地面，480×480 窗口居中，缩放到 200×200
- 男孩：源画布更大，使用 520×520 居中窗口；Dead 躺姿单独裁切并居中
- Dead：以躺姿内容中心为水平中心、源画布底部为地面，同比例缩放
- 每帧底部绘制柔和阴影，保证在透明桌面上有落点

## 5. 皮肤切换无残影

1. **按需加载**：启动只加载当前皮肤的 manifest 与当前动作；切换皮肤时重新加载对应资源
2. **模块级缓存**：manifest、已加载图片、加载中图片去重；Linux 原生窗口按皮肤/状态缓存 Cairo surface
3. **切换策略**：
   - 新皮肤 manifest 已缓存时立即切换
   - 目标状态图未就绪时先显示新皮肤的 idle，加载完成后无缝切到目标状态
   - Linux 原生窗口与 WebView 路径都不会把旧皮肤留在画面上
4. **Linux 原生渲染**：`backend/src/native_pet/` 通过 GTK/Cairo 创建透明窗口，读取 Tauri AssetResolver 中的 WebP；每次状态/帧切换都整面清空透明背景，再绘制当前帧，避免 WebKitGTK 透明窗口的局部重绘残影
5. **Windows/macOS WebView**：Canvas 逐帧 `clearRect` + `drawImage`，切状态/皮肤先清空整张画布；动画期间不触发 React 重渲染
6. Linux 角色窗不依赖 WebKit 合成开关；Tauri 设置/气泡 WebView 仍保留兼容配置。

## 6. 图标与品牌图

应用图标不再使用角色头像，改为**独立的原创扁平图标主题**：

- `heart`（默认推荐，项目品牌爱心）
- `clock`（契合计时/专注）
- `star` / `moon` / `coffee` / `sun` / `leaf` / `heart` / `cloud` / `book` / `flower`
- 设置 → 外观 → 应用图标可切换
- 支持导入自定义 PNG 图标，名称会 trim 并做重复校验
- 切换会同步：托盘图标、宠物/设置/气泡/引导窗口图标、设置页与关于页品牌图、
  Linux 应用菜单、桌面快捷方式图标与显示名称
- Linux 运行中的 Dock/侧边栏图标：同步所有已缓存的图标路径，并刷新 hicolor
  图标主题缓存，让 GNOME Shell 重新加载已创建的应用图标
- 当前图标写入 `~/.local/share/yuzu/app-icon.png`；各主题/自定义图标路径也会
  同步为当前图标，供已缓存的 Shell 图标直接重载
- 默认打包图标：`backend/icons/icon.png`、`512x512.png`、`128x128@2x.png`、`128x128.png`、`32x32.png`、`icon.ico`、`icon.icns`
- 托盘：`backend/icons/tray.png` / `tray-template.png`
- 品牌：`frontend/public/brand/icon-{clock,star,moon,coffee,sun,leaf,heart,cloud,book,flower}.png`
- 生成脚本：`scripts/icon-themes.py`

## 7. 生成流程

```bash
# 1. 下载 CuteGirlFiles.zip 并解压到 scripts/cutegirl/source/png/
#    https://opengameart.org/content/cute-girl-free-sprites

# 2. 下载 FlatBoy.zip 并解压到 scripts/cuteboy/source/png/
#    https://opengameart.org/content/the-boy-free-sprites

# 3. 生成两种风格的 16 套皮肤、manifest、preview
python3 scripts/cutegirl/generate.py
python3 scripts/cuteboy/generate.py
# 生成机器人 / 猫主题风格（需要 scripts/robot、scripts/cat 源素材）
python3 scripts/hero_sprites.py
# 已有资源也可只修复 focus 姿势
python3 scripts/focus_pose.py

# 4. 生成应用图标、托盘与品牌图
python3 scripts/icon-themes.py
```

依赖：Python 3.11+、Pillow、NumPy。
