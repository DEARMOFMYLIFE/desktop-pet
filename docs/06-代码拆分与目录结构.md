# 06 · 代码拆分与目录结构

> 日期：2026-11-13
> 范围：前端 React/TypeScript、后端 Rust/Tauri 与样式层
> 目标：页面/组件/业务文件不超过 200 行；重复 UI 抽公共组件；业务逻辑进 hooks；共享类型放 types/。

---

## 1. 当前拆分原则

1. **页面与组件 ≤ 200 行**：超过后拆成子组件或 hooks。
2. **重复 UI 抽公共组件**：弹窗、清空按钮、日期网格等只保留一份实现。
3. **业务逻辑进 hooks**：数据加载、订阅、设置更新、表单状态不堆在页面里。
4. **数据请求集中到 `lib/ipc/api.ts`**：页面不直接调用底层 IPC。
5. **类型集中到 `types/`**：日期、设置、待办、角色等共享类型统一导出。
6. **后端按领域拆分**：commands / windows / storage / timer / reminders / pet 各自独立。
7. **样式按职责拆分**：全局样式与设置页样式入口都在 200 行以内。

### 2.1 前端拆分记录

| 拆分前 | 拆分后 |
|---|---|
| `DatePickerPopover.tsx` 257 行 | `DatePickerPopover` + `DatePickerCalendar` + `DatePeriodGrid` + `lib/datePicker` + `types/datePicker` |
| 两个大 CSS 文件 | `styles/` 与 `settings/settings/` 下的职责化 CSS partial |
| 多个弹窗各自实现遮罩/标题 | 统一 `Modal`；`ConfirmDialog`、`AppIconDialog`、`TodoDialog` 复用 |
| 多个输入各自实现清空 | 统一 `ClearButton` SVG 图标与 `clearable-field` 样式 |
| 自定义下拉 | `Select` + `SelectMenu` |
| 时间输入 | 项目专用 `DateTimePicker`，不再使用原生 `datetime-local` |
| 页面直接数据请求 | hooks + `lib/ipc/api.ts` |

### 3.1 后端职责约束

- IPC 命令名、SQLite schema、事件名、序列化字段保持稳定。
- 旧数据目录、旧数据库、旧桌面入口和旧角色名通过迁移代码兼容。
- 窗口品牌名、应用标题和桌面名称统一从设置中的角色名称派生。
- 所有后端源文件保持在 200 行以内；超出时按领域继续拆分。

## 4. 桌面启动层

```text
desktop/
├── yuzu                     # Linux x86_64 静态 ELF 启动器
├── launcher/
│   ├── main.go              # 主流程与程序发现
│   ├── env.go               # launcher.env 解析与日志
│   ├── fs.go                # 路径/可执行文件检查
│   ├── ui.go                # 错误提示与帮助
│   ├── build.sh             # 构建 Linux ELF
│   └── prepare.sh           # 准备本机 Tauri 程序与运行库
├── open-app-macos.command
├── open-app-windows.cmd
├── scripts/                 # install-desktop.sh 平台函数
└── resources/               # 本机程序/运行库（不提交）
```

根目录入口：

- `install-desktop.sh`：Linux / macOS / Windows Git Bash 快捷方式安装与卸载。
- `start.sh`：浏览器预览（dev / prod / build / app）。

所有 Go 与 shell 源文件均保持在 200 行以内；Linux ELF 与本地资源分离，
不把 Tauri/WebKitGTK 打进启动器。
