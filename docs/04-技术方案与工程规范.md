## 0. 技术目标与硬约束

| 约束 | 说明 |
|---|---|
| 桌面应用 | 不依赖浏览器打开；独立安装包 |
| Rust 后端 | 所有业务状态、计时、调度、存储、系统集成在 Rust 侧 |
| 跨三端 | Windows 10/11、macOS 12+、Linux（Ubuntu 22.04+） |
| 离线 | 不发起任何网络请求；无账号、无遥测 |
| 本地数据 | SQLite，应用数据目录，可清除 |
| 轻量 | 安装包 ≤ 20MB；空闲内存 < 200MB；空闲 CPU < 1% |
| 不打扰 | 宠物窗不抢焦点；支持点击穿透与显示/隐藏 |

### 0.1 非目标

- 不启动本地 HTTP 服务；前后端只通过 Tauri command/event 通信。
- 不引入 Electron/Node 主进程。
- 不做自动更新、云同步、账号体系。
- 不引入 UI 组件库/图表库（自建小原语，控制体积与风格）。

## 3. 总体架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────────┐
│ Presentation（WebView / React）                              │
│  pet · bubble · settings · onboarding                        │
│  只做渲染、交互、表单校验；状态来自 store，动作走 ipc.ts       │
└───────────────────────────┬──────────────────────────────────┘
                            │ Tauri command / event
┌───────────────────────────▼──────────────────────────────────┐
│ Application（Rust services）                                  │
│  TimerService · ReminderService · PetService · TodoService    │
│  StatsService · SettingsService · OnboardingService           │
│  事务边界、状态机、调度、事件发射                               │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────▼──────────────────────────────────┐
│ Domain（纯逻辑）                                              │
│  TimerState · PomodoroRules · PetStateMachine · ReminderRules │
│  StatsAggregation · Validation · TimeMath                     │
└───────────────────────────┬──────────────────────────────────┘
┌───────────────────────────▼──────────────────────────────────┐
│ Infrastructure                                                │
│  SQLite repositories · WindowManager · Tray · Shortcuts       │
│  Notifications · Autostart · i18n · Logging · SingleInstance  │
└──────────────────────────────────────────────────────────────┘
```

**原则**：

1. **Rust 是唯一事实源**。计时剩余、宠物状态、待办、统计以 Rust 内存/DB 为准；前端只做展示与本地插值。
2. **命令薄、服务厚**。`commands/` 只做参数校验、调用 service、返回 DTO；业务规则在 `domain/` 与 service。
3. **事件单向**。Rust 状态变更后 `emit` 事件；前端不假设自己的操作一定成功，以回传事件/返回值校准。
4. **无跨层回调**。service 不直接操作 DOM/WebView；窗口操作统一走 `windows/`。
5. **锁外发射**。持有 `Mutex/RwLock` 时只拷贝快照，释放后再 `emit`，避免死锁。

### 3.2 线程与异步模型

| 执行体 | 职责 |
|---|---|
| 主线程 | Tauri/窗口/托盘/菜单事件循环；不执行阻塞 IO |
| Tokio runtime | 计时器、提醒调度、待办轮询、事件发射 |
| `spawn_blocking` | SQLite 读写、文件操作 |
| WebView 线程 | 每窗口独立；Canvas 渲染、React 渲染 |

**规则**：

- 所有 command 为 `async`（除纯内存读取），DB 调用一律 `spawn_blocking`。
- 不在 async 中持有 `std::sync::MutexGuard` 跨 `.await`；需要时用 `parking_lot` 并确保临界区无 await，或改用 `tokio::sync::Mutex`。
- 推荐锁顺序：`settings → timer → pet → reminders`；禁止反向嵌套。
- 事件发射频率上限：`pet:position` 在拖拽时 30Hz，其余状态事件按变更触发。

### 3.3 应用状态

```rust
pub struct AppState {
    pub db: Arc<Db>,
    pub settings: SettingsService,   // 内部 RwLock<Settings>，对外 snapshot()/update()
    pub timer: Mutex<TimerService>,
    pub pet: Mutex<PetService>,
    pub reminders: Mutex<ReminderService>,
    pub locale: RwLock<Locale>,
    pub platform: Platform,
}

pub struct Db {
    conn: Mutex<rusqlite::Connection>,
    path: PathBuf,
}
```

- `Db` 内部用 `Mutex<Connection>`；所有查询通过 `Db::call(|conn| ...)` + `spawn_blocking`。
- `Settings` 在启动时从 DB 读取并合并默认值；更新时整体校验、写 DB、更新内存、发事件。
- `TimerService` 持有活动计时任务句柄（`AbortHandle` 或 `CancellationToken`）。
- `PetService` 持有当前状态、目标位置、走动任务句柄。

## 4. 模块设计

### 4.1 应用生命周期

```
main()
  → 初始化日志/panic hook
  → 单实例插件（第二实例唤醒设置窗）
  → 打开 DB / 迁移 / 完整性检查
  → 加载设置 / 语言 / 养成状态 / 计时快照
  → 注册托盘 / 快捷键 / 自启
  → 创建宠物窗（visible=false）
  → 计算位置 / 恢复穿透 / 显示
  → 启动计时恢复、提醒调度、待办轮询
  → 首次运行？打开引导窗
  → run()
```

**退出**：

- `app_quit` 命令：确认弹窗在前端完成 → 停止计时（记录中断）→ 保存快照/位置/养成 → 注销快捷键/托盘 → `app.exit(0)`。
- 系统注销/关机：监听 `RunEvent::ExitRequested`，执行同样的保存逻辑（不弹确认）。
- 崩溃：panic hook 写日志；下次启动关闭孤儿 session。

**不抢焦点**（关键）：

- 目标：点击小人时不激活应用、不抢走当前输入焦点。

- 若不可用：
  - Windows：在 `setup` 后通过 `windows` crate 给 HWND 加 `WS_EX_NOACTIVATE`；
  - macOS：将窗口设为非激活面板（`NSPanel` + `nonactivatingPanel`）或重写 `canBecomeKeyWindow`；
  - Linux/X11：设置 `_NET_WM_WINDOW_TYPE_UTILITY` / `_NET_WM_STATE_SKIP_TASKBAR`，并避免 `focus`。
- 平台扩展代码集中在 `windows/platform/`，用 `#[cfg(target_os)]` 隔离，附最小注释与冒烟项。

**位置与工作区**：

```rust
fn default_position(window: &WebviewWindow, margin: i32) -> LogicalPosition<i32> {
    let monitor = window.current_monitor().ok().flatten()
        .or_else(|| window.primary_monitor().ok().flatten())
        .expect("no monitor");
    let scale = monitor.scale_factor();
    let area = monitor.work_area();          // 若版本无此 API，用平台实现兜底
    let x = area.position.x + area.size.width as i32 - window.outer_size().unwrap().width as i32 - margin;
    let y = area.position.y + area.size.height as i32 - window.outer_size().unwrap().height as i32 - margin;
    LogicalPosition::new(x, y)
}
```

- 统一用**逻辑坐标**计算，写入前按 `scale_factor` 转物理坐标。
- `work_area` 已排除任务栏/Dock；若当前 Tauri 版本无 `work_area()`，在 `windows/platform/` 用 `MonitorFromWindow` + `GetMonitorInfo`（Windows）、`NSScreen.visibleFrame`（macOS）、`_NET_WORKAREA`（X11）兜底。
- 多显示器：保存 `monitor_name` + 相对工作区的归一化坐标 `(nx, ny)`；恢复时按名称查找，找不到回退主屏。
- 拖拽出界：松手时夹取到工作区；尺寸变化后以底部中心为锚点重算。

**气泡定位**：

```rust
fn bubble_position(pet: &Rect, bubble: &Size, placement: Placement) -> PhysicalPosition<i32> {
    let gap = 8;
    let above = pet.y - bubble.height - gap;
    let below = pet.y + pet.height + gap;
    let prefer_above = placement != Placement::Below;
    let y = if prefer_above && above >= pet.work_area.top { above } else { below };
    let x = pet.x + (pet.width - bubble.width) / 2;
    clamp_to_work_area(x, y, bubble)
}
```

- 气泡跟随宠物移动：Rust 在宠物位置变化时节流 30Hz 更新；拖拽中隐藏，结束后 200ms 恢复。
- 气泡窗口尺寸 = 卡片尺寸 + 8px 透明内边距（给阴影）；透明区域会拦截点击，保持内边距尽量小。

**设置窗/引导窗**：

- 普通窗口，居中于当前显示器；最小尺寸见交互文档。
- `settings` 关闭时 `hide()`，再次打开 `show()` + `set_focus()`；恢复上次 Tab（前端 store）。
- `onboarding` 完成后 `close()` + 置 `first_run=false`。

### 4.3 宠物引擎（`pet/`）

**职责**：状态机、自主行为、走动、拖拽、位置持久化、与计时联动。

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum PetState {
    Idle, Walk, Sit, Sleep, Focus, Break, Celebrate, Drag, React, Remind, Droop,
}

pub struct PetService {
    state: PetState,
    base_state: PetState,        // 计时/提醒结束后回到的状态
    deadline: Option<Instant>,   // 一次性状态到期
    walk_task: Option<AbortHandle>,
    position: PersistedPosition,
    mood: i32,
    energy: i32,
}
```

**状态切换**：

```rust
fn transition(&mut self, next: PetState, reason: Reason) -> Option<PetState> {
    if priority(next) < priority(self.state) && !is_preemptive(reason) {
        return None; // 低优先级不打断高优先级
    }
    let prev = self.state;
    self.state = next;
    if is_one_shot(next) {
        self.base_state = prev;
        self.deadline = Some(Instant::now() + duration(next));
    }
    Some(prev)
}
```

- 一次性状态：`Celebrate(3s)`、`React(1.5s)`、`Remind(3s)`。
- `Drag` 由前端 `pointerdown` 阈值触发 `pet_drag_start`，`pointerup` 调 `pet_drag_end`；`pointercancel`/失焦也结束。
- 拖拽使用**手动 IPC 移动**（`pet_drag_move(x, y)`），确保点击/拖拽判定可控；若性能不足，M1 评估改用原生 `startDragging()` + `Moved` 事件。
- 走动：`walk_task` 以 30fps 计算目标点并 `set_position`；到达/被打断即取消。
- 自主行为：1s ticker 检查 `last_interaction`、状态、是否在计时；每 20–60s 掷骰子（`fastrand`）。
- 位置保存：移动结束/拖拽结束/屏幕变化时写入设置；节流 500ms。
- 计时联动：订阅 `TimerService` 的状态事件（进程内 channel 或 service 调用），切 `Focus/Break`；完成时 `Celebrate`。
- 养成：`mood/energy` 变化在 service 内结算，写 DB；低值影响自主行为权重与 `Droop`。

**与前端的事件**：

- `pet:changed` → `{ state, mood, energy, clickThrough, opacity }`
- `pet:position` → `{ x, y, monitor }`（拖拽/走动时节流）
- `pet:click_through` → `{ enabled }`

### 4.4 计时引擎（`timer/`）

**职责**：唯一活动计时、状态机、完成结算、快照恢复、事件发射。

```rust
pub enum TimerKind { Pomodoro, Countdown, CountUp }
pub enum Phase { Focus, ShortBreak, LongBreak }
pub enum Status { Idle, Running, Paused }

pub struct TimerSnapshot {
    pub kind: TimerKind,
    pub phase: Option<Phase>,
    pub status: Status,
    pub total_sec: i64,
    pub remaining_sec: i64,
    pub ends_at: Option<DateTime<Utc>>,
    pub started_at: Option<DateTime<Utc>>,
    pub rounds_completed: u32,
    pub rounds_total: u32,
    pub session_id: Option<i64>,
}

pub struct TimerService {
    active: Option<ActiveTimer>,     // Pomodoro / Countdown / CountUp 的联合
    task: Option<AbortHandle>,       // 当前调度任务；暂停/停止时 abort
}
```

**规则**：

| 规则 | 说明 |
|---|---|
| 单一活动计时 | 番茄钟/倒计时/正计时互斥；启动前确认停止旧的 |
| 权威时间 | `ends_at`（墙钟）+ 进程内 `Instant` 双轨；暂停时保存 `remaining_sec` |
| 完成幂等 | 每个 session 只结算一次；`session_id` + `completed` 标记 |
| 快照 | 每 5s 与每次状态变更写 `timer_snapshot` |
| 恢复 | 未到期 → 暂停并提示继续；已到期 → 结算完成并提示 |
| 孤儿 session | 启动时把 `ended_at IS NULL` 的记录标记 `interrupted`（有快照则补 `actual_sec`） |

**番茄钟转移**：

```
Idle ──start──► Focus(round = completed+1)
Focus ──complete──► completed+1
  ├─ completed % N == 0 → LongBreak
  └─ else → ShortBreak
Focus ──skip──► (不计完成) → ShortBreak / LongBreak（按当前 completed）
Focus ──stop──► Idle（interrupted）
ShortBreak/LongBreak ──complete──► Idle
  └─ autoStartNext → Focus
Break ──skip──► Idle（skipped）
Break ──stop──► Idle（interrupted）
LongBreak 完成 → completed = 0
Paused ──resume──► 原阶段
任意 ──reset──► 丢弃当前 session（不记录）→ 该阶段完整时长、Paused
```

**调度实现**：

```rust
async fn run_timer(app: AppHandle, state: Arc<AppState>, token: CancellationToken, mut snap: TimerSnapshot) {
    loop {
        let now = Utc::now();
        let remaining = snap.ends_at.unwrap() - now;
        if remaining <= Duration::zero() {
            settle_completion(&app, &state, &mut snap).await;
            break;
        }
        tokio::select! {
            _ = token.cancelled() => break,
            _ = tokio::time::sleep(remaining.to_std().unwrap()) => { /* loop re-checks */ }
            _ = tokio::time::sleep(Duration::from_secs(5)) => {
                persist_snapshot(&state, &snap).await;
                detect_clock_jump(&mut snap);
            }
        }
    }
}
```

> 使用 `sleep(remaining)` 会因系统休眠而延后触发；因此额外每 5s 检查墙钟与单调时钟差，检测到休眠/时间跳变后立即重算。也可用 `tokio::time::sleep_until` + `Instant` 组合，具体实现以 M2 测试为准。
> **M2 实际实现**：采用 `timer::run` 的 1Hz 全局 ticker，每秒读取 `ends_at` 重算剩余时间，并每 5 次 tick 持久化快照；上面的 per-timer task 是备选方案，未采用。

**休眠/唤醒检测**：

```rust
let wall_delta = Utc::now() - last_wall;
let mono_delta = Instant::now() - last_mono;
if wall_delta.num_seconds() - mono_delta.as_secs() as i64 > 5 {
    // 系统休眠/时间跳变：按 ends_at 重算
}
```

**统计写入**：

- 开始：`INSERT INTO focus_sessions(..., ended_at=NULL)` 返回 `session_id`。
- 完成：`UPDATE ... SET ended_at=?, actual_sec=?, completed=1`。
- 跳过/停止：`skipped=1` / `interrupted=1`。
- 正计时停止：`actual_sec = elapsed`，`completed=0`；是否插入由 `record` 参数决定。
- 唤醒后若已过期：只结算一次，避免重复通知。

**前端契约**：

- 前端不自己决定“完成”，只显示 `remaining_sec` 本地递减；每 5s 或收到 `timer:changed` 时校准。
- 前端在窗口隐藏时暂停本地 interval；重新可见时立即用最新快照校准。

### 4.5 提醒调度（`reminders/`）

**职责**：喝水/久坐/护眼、待办到点提醒、安静时段、专注策略、持久化。

```rust
pub struct ReminderService {
    states: HashMap<ReminderKind, ReminderState>,
    next_wake: Option<Instant>,
    token: CancellationToken,
}

pub struct ReminderState {
    pub kind: ReminderKind,
    pub enabled: bool,
    pub interval_sec: i64,
    pub next_due_at: Option<DateTime<Utc>>,
    pub last_fired_at: Option<DateTime<Utc>>,
    pub snoozed_until: Option<DateTime<Utc>>,
}
```

**算法**：

1. 启动加载；`next_due_at` 为空 → `now + interval`。
2. 计算最早到期；`sleep_until`；设置变更/ack/snooze 时取消并重排。
3. 到期：
   - 安静时段 → `next_due_at = next_active_start + 5min`；
   - 专注中且配置“暂停全部” → `next_due_at = now + 5min`（每 5 分钟重查，简单可靠）；
   - 否则：发系统通知 + `emit reminder:fired` + 更新 `last_fired_at` + `next_due_at = now + interval`。
4. ack：`next_due_at = now + interval`。
5. snooze：`next_due_at = now + minutes`。
6. 启动时过期处理：若处于活跃时段，延迟 30s 触发一次；否则顺延。

**待办提醒**：

- 独立 30s ticker：查询 `completed=0 AND remind_at <= now AND reminded_at IS NULL`。
- 触发后 `reminded_at = now`；气泡“10 分钟后”把 `remind_at = now+10min`、`reminded_at = NULL`。
- 逾期超过 24 小时仍只提醒一次，不重复轰炸。
- 专注中遵守同一策略（默认仅系统通知）。

**专注状态读取**：通过 `TimerService::snapshot()` 只读快照，不反向持有 timer 锁；若锁顺序为 `timer → reminders`，提醒线程先取 timer 快照再取自身锁。

### 4.6 存储层（`storage/`）

**连接与 PRAGMA**：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
PRAGMA temp_store = MEMORY;
```

**迁移**：

- `schema_migrations(version, applied_at)`；启动时读取最大版本，按顺序执行 `migrations/vN.sql`（`include_str!`）。
- 迁移前用 `VACUUM INTO 'xiaozhu.db.bak-vN-<ts>'` 备份；迁移失败保留原库并进入只读安全模式。
- 启动 `PRAGMA integrity_check`；失败则把原库重命名为 `xiaozhu.db.corrupt-<ts>`，创建新库并提示。

**时间与时区**：

- 所有时间存 UTC RFC3339（`chrono::Utc`）。
- 额外存 `local_date`（`YYYY-MM-DD`），在写入时按本地时区计算；统计按 `local_date` 分组，避免 SQL 时区函数差异。
- 修改系统时区后，仅影响新记录；历史记录保留原 local_date，符合“当时的一天”语义。
- `local_date` 按 `started_at` 的本地日期计算；跨天 session 归属开始日（与 PRD §5.8 一致）。

**设置存储**：

- `app_settings` 一行一个 key，value 为 JSON。
- 启动时读取所有 key，与 `Settings::default()` 深合并；未知 key 保留（向前兼容）。
- 更新时整体序列化 `Settings` 为多个 key 写入（事务）；避免半更新。

**待办排序**：

- `sort_order` 使用 1024 间隔；拖拽插入取相邻均值；间隔 < 2 时整体重排。

- `TrayIconBuilder` + `MenuBuilder`；菜单项 ID 常量集中在 `tray/menu_ids.rs`。

- 使用 `tauri-plugin-global-shortcut`；启动注册三项。

### 4.10 通知（`notifications/`）

- `tauri-plugin-notification`；启动检查权限；首次引导请求。
- 发送失败/权限拒绝：记录一次警告，降级为气泡事件；不阻塞计时。
- 通知内容从 Rust i18n 取；标题/正文参数化（轮次、分钟）。
- 点击通知：平台支持时聚焦设置窗/气泡；不支持则忽略。
- Windows 通知需要稳定的 AppUserModelID；安装包与开发模式行为不同，M5 冒烟验证。

### 4.11 国际化（`i18n/`）

**单一来源**：`frontend/shared/locales/{zh-CN,en-US}.json`。

- Rust：`include_str!` 编译进二进制；启动解析为扁平 `HashMap<String, String>`。
- 前端：Vite alias `@locales` 指向 `frontend/shared/locales`，按当前 locale 动态 import。
- key 使用点号：`settings.general.language`；嵌套 JSON 扁平化。
- 插值：`{name}`、`{n}`；简单替换，不做 ICU。
- 复数：v1 文案避免复数敏感表达（如用 `Tasks: {n}`）；确需复数时实现 `_one/_other`。
- 缺失：回退 `en-US`，开发环境 `console.warn`；Rust 记录 `tracing::warn`。
- 语言解析：`sys-locale` → `zh*` 为 `zh-CN`，其他 `en-US`；手动覆盖优先。
- 切换：更新设置 → 重载前端字典 → `emit locale:changed`；托盘/通知使用 Rust 字典即时生效。

## 6. 数据库与统计

### 6.1 仓库接口

```rust
pub struct FocusRepo;
impl FocusRepo {
    pub fn insert_started(conn: &Connection, s: &NewSession) -> Result<i64>;
    pub fn finish(conn: &Connection, id: i64, end: FinishKind) -> Result<()>;
    pub fn stats(conn: &Connection, from: NaiveDate, to: NaiveDate) -> Result<Vec<DailyStat>>;
    pub fn close_orphans(conn: &Connection) -> Result<usize>;
}
```

- 所有 SQL 参数化；禁止字符串拼接。
- 统计查询：

```sql
SELECT local_date,
       SUM(CASE WHEN kind='pomodoro_focus' AND completed=1 THEN actual_sec ELSE 0 END) AS focus_sec,
       SUM(CASE WHEN kind='pomodoro_focus' AND completed=1 THEN 1 ELSE 0 END)          AS rounds,
       SUM(CASE WHEN kind='pomodoro_focus' THEN 1 ELSE 0 END)                          AS started,
       SUM(CASE WHEN kind IN ('pomodoro_break') AND completed=1 THEN actual_sec ELSE 0 END) AS break_sec
FROM focus_sessions
WHERE local_date BETWEEN ?1 AND ?2
GROUP BY local_date
ORDER BY local_date;
```

- 完成率 = `rounds / started`（`started=0` 返回 `null`，前端显示 `—`）。
- 今日范围：本地 `today` 单日；7/30 天含今日，向前推 6/29 天。
- 计时器记录不影响番茄轮次，但可在“专注分钟”中单列（P1 先不展示，保留字段）。

### 6.2 数据生命周期

- 专注记录：永久保留；P2 可加清理。
- 待办：完成后保留；用户可删除。
- 日志：7 天滚动。
- 清除数据：关闭 DB → 删除 `xiaozhu.db*`、日志、缓存 → 重新初始化 → 重启/回到引导。
- 备份：迁移前 `VACUUM INTO`；保留最近 3 份。


- 降级不影响计时、提醒、待办等核心功能。
- 降级状态写入日志，不写入用户设置（环境变化后可恢复）。

### 7.2 置顶与焦点

- `always_on_top` 默认 true；设置关闭后窗口仍在普通层级。
- 宠物窗不抢焦点（§4.2）；右键菜单弹出时可短暂获得菜单焦点，关闭后归还。
- 设置窗打开时正常抢焦点（用户主动操作）。
- macOS Accessory：不在 Dock 显示；设置窗仍可通过托盘打开。
- Windows：宠物窗 `skipTaskbar`；设置窗正常显示任务栏按钮。

### 7.3 屏幕与 DPI

- 位置计算全部用逻辑坐标；写入系统前乘 `scale_factor`。
- 监听 `ScaleFactorChanged` / `Moved` / `Monitor` 变化：
  - 重新夹取位置；
  - 重新计算角色尺寸；
  - 通知前端重绘 Canvas。
- 角色素材按 2x 设计（256px 帧），在 1x/1.5x/2x 下缩放，避免模糊。
- 混合 DPI 多屏：窗口跨屏时按当前所在显示器缩放；移动结束后重新栅格化。

### 7.4 全屏/演示

- 不自动检测全屏（跨平台 API 不稳定）。
- 提供 `toggle_visible` 快捷键与托盘开关；首次引导提示。
- 点击穿透状态与隐藏状态持久化；重启恢复。
- 屏幕共享/录制场景由用户主动隐藏；文档说明。

```json
    "focus":   { "file": "focus.webp",   "frames": 6, "fps": 8,  "loop": true },
    "break":   { "file": "break.webp",   "frames": 4, "fps": 6,  "loop": true },
    "celebrate": { "file": "celebrate.webp", "frames": 8, "fps": 12, "loop": false },
    "drag":    { "file": "drag.webp",    "frames": 2, "fps": 8,  "loop": true },
    "react":   { "file": "react.webp",   "frames": 6, "fps": 12, "loop": false },
```

- 每个状态一张横向 sprite sheet：宽 = `frameSize[0] * frames`，高 = `frameSize[1]`。

- `hitbox` 为归一化 `[x, y, w, h]`，用于点击命中判断（不改变窗口级穿透）。
- 素材缺失时加载 `frontend/public/assets/character/placeholder/`（内置几何小人），并记录 `ASSET_MISSING`。

### 8.2 Canvas 渲染

```ts
class SpritePlayer {
  constructor(manifest: Manifest, basePath: string) {}
  preload(states: PetState[]): Promise<void>;
  play(state: PetState): void;
  tick(now: number): void;   // rAF 驱动
  draw(ctx: CanvasRenderingContext2D, dpr: number): void;
}
```

- 预加载优先级：`idle/walk/sit/sleep` → `focus/break` → 其余；懒加载避免启动卡顿。
- `requestAnimationFrame` 驱动；不可见时暂停（`document.visibilityState` + 窗口 `isVisible`）。
- 一次性状态播完回调 `onEnd`；前端通知 store 或等待 Rust 的 `pet:changed` 校准。
- 减少动态：只播 `idle` 第 0/3 帧（2s 切换）；不播走动/跳跃。
- 背景节流：若 WebView 节流 rAF，Rust 以 12fps 发 `pet:frame` 事件驱动（M0 验证是否需要）。

### 8.3 素材规范

| 项 | 规范 |
|---|---|
| 帧尺寸 | 200×200，透明背景 |
| 格式 | WebP（alpha），回退 PNG |
| 角色高度 | 约 200px（帧内留 28px 上下边距） |
| 描边 | 统一 4–6px 深色描边，圆角 |
| 调色 | 暖色主色 + 1 个点缀色；避免高饱和荧光 |
| 帧数 | 循环 4–8 帧；一次性 6–8 帧 |
| 命名 | `state.webp`，全小写 |
| 许可 | CC0 / MIT / Apache-2.0 / CC-BY 4.0（需署名）；记录作者与来源 |

**占位角色**：几何圆头 + 简单表情，至少覆盖 `idle/react/celebrate` 三态，保证素材未到位时 UI 可开发。

## 9. 计时与提醒的边界处理

### 9.1 系统休眠/唤醒

- 每次 5s 检查墙钟与单调时钟差；差值 > 5s 视为休眠/时间跳变。
- 运行中且 `ends_at <= now`：结算完成一次。
- 暂停中：不自动继续；`remaining_sec` 不变。
- 正计时：按墙钟补足 `actual_sec`（休眠期间是否计入由产品决定；v1 计入，符合“墙钟时间”直觉）。
- 提醒：休眠期间错过的提醒只补一次；多条过期合并为一条“你有 N 条提醒”。

### 9.2 系统时间修改

- 前跳：按 `ends_at` 结算；若前跳超过剩余时间，立即完成。
- 回拨：不重复计时；以 `remaining_sec` 与单调时钟为准，必要时暂停并提示“检测到系统时间变化，计时已校准”。
- 统计按 `local_date` 写入，不因回拨产生负时长。

### 9.3 应用退出/崩溃

- 正常退出：停止计时 → 记录 `interrupted` → 保存快照/位置/养成。
- 崩溃：快照每 5s 落盘；下次启动关闭孤儿 session，提示“上次计时未正常结束”。
- 强杀：最多丢 5s；不影响待办/设置。

### 9.4 计时互斥

- `TimerService::start` 先检查当前活动计时；有则返回 `TIMER_CONFLICT`，前端弹确认。
- 确认后调 `timer_stop` 再 `timer_start`；Rust 侧仍二次校验，避免竞态。

## 12. 编码规范

### 12.1 Rust

- Edition 2021；`rust-toolchain.toml` 固定 stable。
- `cargo fmt`；`cargo clippy -- -D warnings`。
- `#![deny(unsafe_code)]`；平台扩展如必须 `unsafe`，集中在 `windows/platform/` 并附 `// SAFETY:` 注释。
- 模块按领域拆分；`commands/` 不写业务规则。
- 错误统一 `AppError`；命令不 `unwrap`/`panic`（启动期不可恢复错误除外，需记录日志）。
- 时间：持久化用 `DateTime<Utc>`；调度用 `Instant`；禁止用本地时间做计算。
- 锁：临界区短；不在持锁时 `await` 或 `emit`。
- DB：参数化 SQL；事务用 `conn.transaction()`；迁移只增不改。
- 日志：`tracing::{info,warn,error,debug}`；不记录用户正文。
- 命名：类型 `CamelCase`，函数/变量 `snake_case`，常量 `SCREAMING_SNAKE_CASE`。
- 文档：公开 service/命令必须有 `///` 注释，说明副作用与错误。

### 12.2 TypeScript / React

- `strict: true`；禁止 `any`、`@ts-ignore`、`@ts-nocheck`。
- ESLint + Prettier；提交前 `npm run lint`。
- 组件 ≤200 行；窗口组件只编排，逻辑进 hooks/store。
- 所有 IPC 经 `frontend/src/lib/ipc.ts`；组件禁止直接 `invoke` / `listen`。
- 颜色/间距/圆角只用 `tokens.css` 变量；禁止硬编码。
- 文案一律走 `t(key)`；禁止 JSX 里写死中英文。
- 状态：Zustand store 按域拆分；派生值用 selector，不重复存。
- 错误：统一 `IpcError`；表单错误就近展示；全局错误用 Toast。
- 可访问性：语义标签、`aria-*`、键盘可达；新组件必须过键盘检查。
- 测试：纯函数 100% 覆盖；关键组件有交互测试。

### 12.3 提交与评审

- Conventional Commits：`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`。
- PR 模板检查：
  - [ ] 三端构建/冒烟（至少 Linux + CI 其他两端的 build）
  - [ ] `cargo fmt/clippy/test`、`npm lint/test/build`
  - [ ] 新增文案中英齐全
  - [ ] 无网络请求/无新增权限
  - [ ] 性能预算未退化
  - [ ] 文档/ADR 已更新
- 破坏性变更需写 ADR 并更新本文。

## 15. 架构决策记录（ADR）

| ID | 决策 | 理由 | 替代方案 |
|---|---|---|---|
| ADR-001 | Tauri 2 而非 Electron | Rust 主进程、体积小、系统集成够用 | Electron + sidecar |
| ADR-002 | SQLite 而非 JSON | 聚合、迁移、并发写入更稳 | JSON / IndexedDB |
| ADR-003 | Canvas 2D + sprite sheet | 与 CC0 素材匹配、状态机简单 | Live2D / Lottie / 3D |
| ADR-004 | 小型贴边窗口而非全屏覆盖 | 性能、误触、实现复杂度更优 | 全屏透明层 |
| ADR-005 | 独立气泡窗 | 避免宠物窗透明区拦截点击；定位/动效独立 | 宠物窗内绘制气泡 |
| ADR-006 | Rust 权威计时 | 休眠/重启/后台可靠；前端只做插值 | 前端计时 |
| ADR-007 | 共享 locale JSON | Rust 通知与前端 UI 同一份文案 | 两边各维护 |
| ADR-008 | 设置即时保存 | 减少“保存”心智；桌面工具惯例 | 显式保存按钮 |
| ADR-009 | 不引 UI 库/图表库 | 体积小、风格统一、可控 | shadcn / Recharts |
| ADR-010 | 单活动计时 | 避免多计时冲突与统计歧义 | 多计时并行 |

## 17. 附：关键接口示例

### 17.1 前端 `lib/ipc.ts`

```ts
import { invoke } from '@tauri-apps/api/core';
import { listen, type UnlistenFn } from '@tauri-apps/api/event';

export class IpcError extends Error {
  constructor(public code: string, message: string, public details?: unknown) {
    super(message);
  }
}

export async function call<T>(cmd: string, args?: Record<string, unknown>): Promise<T> {
  try {
    return await invoke<T>(cmd, args);
  } catch (e) {
    const err = e as { code?: string; message?: string; details?: unknown };
    throw new IpcError(err.code ?? 'INTERNAL', err.message ?? 'unknown', err.details);
  }
}

export function on<T>(event: string, handler: (payload: T) => void): Promise<UnlistenFn> {
  return listen<T>(event, (e) => handler(e.payload));
}
```

### 17.2 Rust command 示例

```rust
#[tauri::command]
pub async fn timer_start(
    app: AppHandle,
    state: State<'_, AppState>,
    req: TimerStartRequest,
) -> Result<TimerSnapshot, AppError> {
    let settings = state.settings.snapshot();
    let snapshot = {
        let mut timer = state.timer.lock();
        timer.start(req, &settings)?
    }; // 锁释放
    app.emit("timer:changed", &snapshot)?;
    Ok(snapshot)
}
```

### 17.3 设置更新示例

```rust
#[tauri::command]
pub async fn settings_update(
    app: AppHandle,
    state: State<'_, AppState>,
    settings: Settings,
) -> Result<Settings, AppError> {
    settings.validate()?;
    let canonical = state.settings.update(settings).await?;
    app.emit("settings:changed", &canonical)?;
    Ok(canonical)
}
```
