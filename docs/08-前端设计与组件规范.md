# 08 · 前端设计与组件规范

> 日期：2026-11-11
> 目标：让“小柚”看起来像一款安静、精致、可信赖的桌面陪伴工具，而不是通用后台模板。

---

## 1. 视觉方向

**Cozy desk companion / 温暖桌面文具感**

- 暖米色背景、奶白内容面、珊瑚色行动点。
- 圆角收紧：按钮 8px、卡片 10px、输入框 6px。
- 用 1px 边框和极轻阴影建立层次，不用厚阴影和大圆角。
- 图标统一 Lucide 线性图标，禁用 emoji 作为 UI 图标。
- 字体使用系统 UI 字体，标题只比正文大半级到一级。
- 动效只表达状态：hover、focus、toast、spinner，不做装饰性编排。

## 2. Design tokens

定义位置：`frontend/src/styles/tokens.css`

| Token | 值 / 用途 |
|---|---|
| `--bg` | 页面背景 |
| `--surface` | 卡片/侧栏表面 |
| `--surface-muted` | 次级表面 |
| `--text` / `--text-secondary` | 主/次文字 |
| `--border` | 细边框 |
| `--accent` / `--accent-soft` / `--accent-ink` | 主行动、柔和底色、可读强调文字 |
| `--success` / `--warning` / `--danger` | 语义状态 |
| `--radius-xs/sm/md/lg/xl` | 4 / 6 / 8 / 10 / 12px |
| `--shadow` / `--shadow-sm` / `--shadow-xs` | 三层轻阴影 |

Tailwind 主题在 `frontend/tailwind.config.js` 中映射这些变量，组件类通过 `@apply` 使用。

## 3. 项目级组件

### Button / IconButton

`components/ui/Button.tsx`

- variants：`primary` / `secondary` / `ghost` / `quiet` / `danger`
- sizes：`sm` / `md`
- 支持 `loading`、leading/trailing icon。
- 所有新按钮优先使用 `<Button>`；图标按钮使用 `<IconButton label=...>`。

### Input / Textarea

`components/ui/Input.tsx`

- 统一高度、边框、focus ring、placeholder、invalid 状态。
- 表单输入优先使用 `<Input>` / `<Textarea>`，不要重复写 `className="input"`。

### Select

`components/ui/Select.tsx`

- 非原生 `<select>`；自定义 listbox。
- 支持键盘 `ArrowUp/Down/Home/End/Enter/Escape/Tab`。
- 菜单通过 portal 渲染，避免被 `overflow` 裁切。
- 用于语言等设置项。

### NumberInput

`components/ui/NumberInput.tsx`

- 自定义数字步进器：`- / +`、单位、min/max clamp。
- 隐藏浏览器原生 number spinner，统一数字排版。

### SearchField

`components/ui/SearchField.tsx`

- 搜索图标、清除按钮、`role="search"`。
- 待办页用它按标题/备注搜索。

### Checkbox

`components/ui/Checkbox.tsx`

- 原生 input + 自定义方框；支持 `aria-label`、disabled、focus ring。
- 待办完成状态使用它。

### Card / SettingsCard

- `Card` 是最小卡片原语。
- `SettingsCard` = Card + 标题 + 描述。
- 页面优先用 `SettingsCard`，不要重复写 `section.card`。

### 布局

- `SettingsSidebar`：侧边栏 + Tab 导航。
- `SettingsHeader`：设置页 Header。
- `BubbleShell`：气泡/提醒 Header。
- `OnboardingHeader/Footer`：引导流程布局。

## 4. 页面约定

- 页面只负责组合组件和 hook，不直接写 IPC。
- 所有数据动作经 `hooks → lib/ipc/api.ts`。
- 破坏性操作统一用 `ConfirmDialog`。
- 加载态统一用 `LoadingPane`。
- 表单错误使用 `.todo-error` / `Notice`，成功反馈用 Toast。
- 新页面必须复用上述组件和 tokens；没有复用理由才新增 CSS 类。

---

## 5. 角色资源

- 角色为 Cute Girl（pzUH，CC0）形象，由 `scripts/cutegirl/` 生成。
- 16 套 Cute Girl 配色皮肤，默认珊瑚；所有皮肤共享 11 种动作状态。
- 11 个动作：idle / walk / sit / sleep / focus / break / celebrate / drag / react / remind / droop。
- `PetStage` 使用 DOM 精灵背景渲染（`background-position`），只显示当前帧；不再使用 Canvas 叠加绘制。
- 素材源文件在 `frontend/public/assets/character/`，manifest 版本 2。

## 6. Skill 使用记录

本轮按用户指定的 `impeccable` skill 的 Operate 模式执行：

- 先审计现有视觉、组件、间距、圆角、阴影和状态。
- 以“产品 UI 的熟悉感”优先，不引入奇怪的控件。
- 建立统一组件词汇，避免每页一种按钮/下拉/输入框。
- 只保留有状态意义的动效；未引入无意义装饰。
- 完成后用真实浏览器截图检查设置页 8 个 Tab、下拉菜单、待办页、引导页、气泡和宠物。
